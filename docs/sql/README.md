# 메뉴별 리뷰 DB 적용

1. 프로젝트가 접속하는 Oracle 계정으로 SQL Developer에 로그인합니다.
2. 기존 `tbl_member(userid)`가 있는지 확인합니다. 메뉴 관련 객체가 이미 있다면 신규 생성 SQL을 실행하지 말고 구조를 먼저 비교합니다.
3. `menu-review.sql`을 열고 **스크립트 실행(F5)** 합니다. Oracle DDL은 자동 커밋되며, 오류가 나면 이미 생성된 객체가 남을 수 있습니다. 원인을 확인하기 전 반복 실행하지 마세요.
4. 실제 메뉴와 오늘/내일의 식단을 입력합니다. `serve_date`는 `TRUNC(SYSDATE)`처럼 시간 없는 날짜로 입력합니다. 개발용 예시가 필요하면 `menu-review-example.sql`을 별도로 실행합니다. 예시는 실제 식단이 아니며 운영 DB에서 그대로 실행하지 않습니다.
5. 프로젝트를 다시 빌드·배포하고 `/main`을 엽니다. 로그인 후 오늘 제공 메뉴마다 리뷰를 등록할 수 있습니다.

## 식단 입력 규칙

- 식단 행 하나는 날짜·시간대별 메뉴 한 항목입니다. 여러 메뉴는 여러 행으로 입력합니다.
- 실제 배식 확정 전에는 `actual_menu_id`, `is_matched`를 모두 NULL로 둡니다.
- 실제 배식이 확정되면 `actual_menu_id`를 설정하고 예정 메뉴와 같으면 `is_matched='Y'`, 다르면 `'N'`으로 함께 갱신합니다.
- 같은 날짜·시간대의 실제 제공 메뉴는 중복 등록할 수 없습니다. 실제 메뉴 미확정 행은 여러 개 등록할 수 있습니다.
- 리뷰가 달린 실제 메뉴를 교체하면 FK가 차단합니다. 기록을 다른 메뉴의 리뷰로 바꾸지 마세요.
- 리뷰는 로그인 사용자의 `userid`와 연결됩니다. 마이페이지는 추후 이 컬럼으로 조회하면 되며 별도 복제 테이블이 필요하지 않습니다.
- 오늘 여부는 정의서의 `SYSDATE` 기준입니다. Oracle 서버의 날짜·시간대가 학교 운영 시간과 맞아야 합니다.

## 검증

`ex06_2`에서 `mvn -Dtest=MenuReviewServiceTests,MenuReviewControllerTests,MenuReviewMapperTests,MenuReviewSecurityTests test`를 실행합니다. 이 테스트들은 DB에 접속하거나 데이터를 삽입하지 않습니다. 기존 `MemberTests`는 데이터 삽입 테스트이므로 함께 실행하지 않습니다.

테스트 DB 적용 후에는 두 계정으로 등록·중복 등록·타인 수정 차단·삭제·새로고침 후 유지·페이지 이동을 확인하세요. 내일 식단과 실제 메뉴 미확정 항목은 평가할 수 없어야 합니다. 서버의 실제 SQL 실행, 평균 별점 동시 갱신, 날짜 경계 동작은 DB 연결 환경에서 별도 확인이 필요합니다.
