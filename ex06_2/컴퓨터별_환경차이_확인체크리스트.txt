[체크포인트 1] STS 'About' 창에서 Lombok 실제 주입 여부 확인 (가장 확실함 ★★★)
--------------------------------------------------------------------------------
롬복 에이전트가 STS 프로그램 메모리에 정상 침투했는지는 이 창에서 1초 만에 확인 가능합니다.

- 확인 방법:
  STS 상단 메뉴 [Help] -> [About Spring Tool Suite 3] (또는 [About Eclipse]) 클릭
- 비교할 부분:
  팝업창 하단 텍스트 영역을 아래로 스크롤하여 확인합니다.
  * 정상 작동 PC:
    "Lombok v1.18.0 'Envious Ferret' is installed. https://projectlombok.org/" 문구가 존재함.
  * 오류 발생 PC:
    해당 문구가 아예 없거나, 초기화 실패 에러가 찍혀 있음.
    (문구가 없다는 것은 STS.ini의 롬복 설정이 JVM 부팅 시 무시/탈락되었다는 뜻입니다.)


[체크포인트 2] STS.ini 파일 내용 1:1 대조
--------------------------------------------------------------------------------
두 컴퓨터의 STS 설치 폴더 내 [STS.ini] 파일을 메모장으로 열어 비교합니다.

- 비교할 부분:
  1) -javaagent: 경로 표기 방식
     * 다른 PC: -javaagent:lombok.jar (상대경로) 형태인지 확인
     * 현재 PC: -javaagent:C:\Users\... (긴 절대경로, 특수문자 포함 여부)
  2) 추가 옵션 존재 여부
     * 다른 PC에 -Xbootclasspath/a:lombok.jar 옵션이 함께 들어가 있는지 확인
  3) -vm 옵션 위치 및 경로
     * -vm 옵션이 가리키는 javaw.exe 경로와 -vmargs 위에 정확히 위치했는지 대조


[체크포인트 3] Java(JDK)의 상세 마이너 버전 및 제조사(Vendor) 대조
--------------------------------------------------------------------------------
단순히 "15버전"이라는 것 외에 마이너 패치 버전과 배포 제조사에 따라 리플렉션 보안 정책이 다릅니다.

- 확인 방법:
  각 컴퓨터의 명령 프롬프트(cmd)에서 아래 명령 실행
  cmd > java -version
- 비교할 부분:
  * 마이너 패치 버전: 15.0.0 vs 15.0.1 vs 15.0.2 (현재 PC는 15.0.2)
  * 제조사(Vendor):
    - Oracle 정식 JDK ("Java(TM) SE Runtime Environment")인지
    - Eclipse Temurin / Adoptium / Corretto 등의 OpenJDK 계열인지 대조
    (제조사 및 마이너 버전에 따라 내부 API 접근 차단 강도가 다릅니다.)


[체크포인트 4] STS 내부 'Installed JREs' 컴파일러 환경 대조
--------------------------------------------------------------------------------
STS 프로그램 자체는 Java 15로 떴더라도, 프로젝트 코드를 빌드할 때 사용하는 JDK가 다를 수 있습니다.

- 확인 방법:
  STS 상단 메뉴 [Window] -> [Preferences] -> [Java] -> [Installed JREs] 클릭
- 비교할 부분:
  * 다른 PC에는 Java 15 외에 Java 1.8(JDK 8)이 함께 등록/체크되어 있는지 확인
  * 왼쪽 서브메뉴 [Installed JREs] -> [Execution Environments] -> [JavaSE-1.8] 클릭 시,
    우측에 Compatible JRE로 어떤 JDK가 매핑되어 있는지 확인
    (현재 PC는 JDK 15 하나만 단독 설치되어 있어 1.8 타겟도 15 엔진으로 컴파일됨)


[체크포인트 5] STS 에러 로그(.log) 파일 대조
--------------------------------------------------------------------------------
롬복이 왜 부팅 시 탈락했는지는 로그에 스택 트레이스로 기록됩니다.

- 확인 방법:
  각 워크스페이스의 [.metadata/.log] 파일을 메모장으로 열기
  (또는 STS 내부 메뉴 [Window] -> [Show View] -> [Other...] -> [General] -> [Error Log])
- 비교할 부분:
  * "lombok" 또는 "InaccessibleObjectException" 검색
  * 에러가 났던 PC에는 STS 기동 시 롬복이 내부 컴파일러(JDT)에 접근하다 거부당한 로그가 남음.
