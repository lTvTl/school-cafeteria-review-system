# 관리자 기본 화면

## 구현 범위

- `/admin`에 로그인 계정과 관리자 권한을 보여주는 기본 화면을 제공합니다.
- 왼쪽 메뉴의 마지막 항목에 남색 관리자 메뉴를 표시합니다. `ROLE_ADMIN` 계정에서만 보입니다.
- `/admin`과 `/admin/**`는 주소를 직접 입력해도 관리자만 접근 가능합니다. 비로그인은 로그인 화면, 일반 회원은 기존 접근 거부 화면으로 이동합니다.
- `AdminController`에도 관리자 권한 검사를 적용합니다. 기존 로그인·리뷰 보안·CSRF 설정은 유지합니다.
- 서버 상태와 현재 접속 세션 수를 표시하고 2초마다 갱신합니다. 수동 새로고침도 가능합니다.
- 식단 등록, 회원·리뷰 관리 기능은 포함하지 않습니다.

## 서버 현황 기준

서버 상태 그래프를 위에, 현재 접속자 그래프를 아래에 배치합니다. 페이지를 연 이후 최근 60초의 측정값을 표시합니다. 서버 그래프는 JVM 힙 사용률(0~100%), 접속자는 활성 세션 수(자동 눈금)입니다. CPU/GPU 사용률을 측정하는 기능은 아닙니다. 연결 실패 구간은 선을 이어 붙이지 않으며, 새로고침하면 그래프 이력은 초기화됩니다.

- `serverStatus`: 현재 JVM 힙 사용률이 90% 미만이면 `NORMAL`, 이상이면 `BUSY`. 전체 서버/DB/네트워크의 종합 건강도 판정은 아닙니다.
- `memoryUsage`: JVM이 사용하는 힙 메모리를 최대 힙 크기로 나눈 비율입니다. OS 전체 메모리 사용률과 다릅니다.
- `activeUserCnt`: `SessionListener`가 추적하는 현재 서버 인스턴스의 활성 HTTP 세션 수입니다. 로그인·비로그인·관리자 포함이며 실제 사람 수나 누적 방문자 수가 아닙니다. 같은 브라우저 탭들은 보통 세션을 공유하고, 다른 브라우저/시크릿 창은 별도 세션입니다.
- 세션 종료/만료 시 감소합니다. 브라우저를 닫았다고 즉시 감소하지는 않습니다. 서버 재시작/세션 복원에 따라 수치는 달라질 수 있습니다.
- `/admin/status`도 관리자만 조회할 수 있습니다. 응답을 캐시하지 않으며, 조회 실패 시 정상 표시와 이전 접속자 수를 지우고 확인 불가로 표시합니다.
- 통계는 메모리에서 계산하므로 추가 SQL이나 테이블은 필요 없습니다.

## 테이블과 권한

변수명 정의서의 `tbl_member(userid)`와 `tbl_member_auth(userid, auth)`를 그대로 사용합니다. 두 테이블은 [공통 DB SQL](../sql/common/database.sql)에 있으므로 별도 관리자 테이블을 만들지 않습니다.

관리자 접근에는 기존 회원의 `tbl_member_auth`에 `ROLE_ADMIN` 권한이 필요합니다. 현재 관리자 권한 부여 전용 SQL 파일은 없으며, 향후 해당 SQL은 `sql/admin/`에 둡니다. 로그인 가능한 계정과 권한은 별도로 준비해야 합니다.

이 SQL은 해당 계정에 `ROLE_ADMIN`을 추가하고 커밋합니다. 비밀번호나 기존 권한은 변경하지 않습니다. 이미 같은 권한이 있으면 추가하지 않습니다. 기존 권한이 중복돼 있으면 중단합니다. 적용 후 로그아웃하고 다시 로그인해야 새 권한이 반영됩니다. 실제 DB에는 자동 실행하지 않습니다.

## 확인 방법

1. 비로그인 상태에서 `/admin` 접근: 로그인 안내, 관리자 메뉴 숨김.
2. 일반 회원 로그인 후 직접 접근: 접근 거부, 관리자 메뉴 숨김.
3. 관리자 로그인: 왼쪽 마지막 남색 메뉴 표시, 관리자 화면에서 자신의 아이디 확인.
4. `/admin/`과 하위 경로도 일반 계정 접근 차단. 아직 없는 하위 화면은 관리자라도 페이지가 제공되지 않습니다.
5. 모바일에서 메뉴 펼침과 관리자 링크 이동 확인.
6. 별도 시크릿 창에서 홈을 열고 관리자 화면을 갱신해 세션 증가 확인. 로그아웃/세션 만료 후 감소 확인. 일반 로그아웃은 로그인 화면에서 새 세션을 만들 수 있어 전체 수가 즉시 줄지 않을 수 있습니다.
7. 서버 연결이 끊기면 다음 갱신에서 확인 불가로 바뀌는지, 연결 복구 후 다시 갱신되는지 확인.

검증: Java 전체 컴파일과 JUnit 41개, 상태 갱신 JavaScript 검사 통과. 세션 생성/종료/ID 변경/동시성, 상태 응답, 관리자 접근·비관리자 차단·CSRF를 확인했습니다. Maven 대신 JDK 15와 로컬 의존성으로 검사했으며 로그는 `ex06_2/target/admin-status-check`에 있습니다. JavaScript 검사는 `ex06_2`에서 `node src/test/js/admin-status.test.js`로 실행합니다.

실제 DB 권한 부여와 브라우저 화면 검증은 미실시입니다. `web.xml`에 세션 리스너를 추가했으므로 Clean 빌드 후 Tomcat을 재시작하여 배포하세요.
